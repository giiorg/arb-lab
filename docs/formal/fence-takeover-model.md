### The control-witness round (slice E item 2, 2026-08-02)

Model (a) has asked its controls since slice C whether their counterexamples
demonstrate the **harm** or only the **flag**. Model (b)'s five had never been
asked, and NC1–NC4 predate the question entirely. All six probes were
**REACHED**: every control's stated harm is real, and TLC had simply been
reporting a shallower witness.

**The degeneracy was systematic, not four accidents.** Every invariant here can
be tripped two ways — by a cheap *surrogate* for exposure (an order sitting
live, unfilled) or by exposure itself — and the surrogate is always exactly one
`VEntryFill` closer to `Init`. Breadth-first search returns it every time.
Three of the four safety witnesses end `pos = "flat"`, `hadExposure = FALSE`.

**NC3 is the exception, and not by luck:** `ActCanaryUnfencedClose` carries
`pos ≠ "flat"` in its own guard, so no witness of it can be flat. A control
whose harmful precondition is a **guard of the action it enables** cannot have a
degenerate witness in that dimension — which is the general form, and the
property the other three lack.

**Two suite defects this surfaced, both invisible from a green run:**

1. **`I2_HostIndependentCoverage` had never been violated by any run.** It is
   listed in exactly two configs (NC2, NC4) and both report `I3` — because TLC
   halts at the first violation, so a shallower `I3` **ends the search before
   the `I2` state exists to be found**. The configs' "I2 or I3" wording is what
   made it invisible. W2 and W6 now demonstrate it under both controls.
2. **The prose in this artifact carried harm the runs never showed.** §1's NC2
   line said "the entry *then fills* into a coverage hole" and §2's FM-1 trace
   said "→ I3, **then I2**". NC4 never violates I2, and both traces stop before
   any fill. The claims were *true about the system* — W6 proves it — and that
   is exactly why four review rounds passed over them: a false claim gets
   challenged, while a true claim resting on a run that did not show it reads as
   verified. Both sentences are now scoped to what their run reports, with the
   probe that supplies the rest named beside them.

**What separates every degenerate witness from its harm is a fill** — the one
event in this system no component gets to decline. A control that stops at "the
flag flipped" is reporting a state the venue can convert into the real damage
unilaterally. That is the argument for why "shortest counterexample" and
"adequate evidence" are different things, and it generalizes past this model.

**W6 exists because W4's trace was read.** W4 was REACHED, and reading it showed
W4 to be only *half* of NC4's claim: exposure re-admitted, `plan` still
`"active"`, coverage intact. `ActDeactivate` guards on `actuatedFlat ∧ plan =
"active" ∧ actReadyOK` and on **nothing about position**, so the stale record
re-drives the tombstone straight over the re-admitted exposure — reached at 12
states, NC4's committed 11-state trace plus one `VEntryFill`. **A probe being
violated says the state is reachable; only the trace says whether it is the harm
the control names.**

**And one prediction was wrong, which is why these are runs and not sentences.**
W2 was written claiming the tombstone-over-exposure state was reachable *only*
through `BotDeactivate`'s `botCloseLive` disjunct — the issuance-gated bug
proper. It is not: the witness tombstones a **flat** package whose entry is
still live, then lets the entry fill. The `botCloseLive` disjunct is not
exercised even by the probe. What that says about `I3` is the useful part:
**`I3`'s `NoLiveOrders` conjunct is not tidiness beside `I2`, it forbids the
precursor of an `I2` violation.** A terminal declared while any order is live is
one uncontrolled venue event away from exposure under a tombstoned plan. `I2`
is not decoration — `I3` is what keeps it green.

**NC5 is a new *kind* of negative control** — the first that proves a *temporal property* bites rather than an invariant. It exists because this round's two predecessors both failed the same way: Cx7-2 found a convergence property that had been vacuous for branch 1 for a whole round, and Cx7-3 found a completion path with no capability property over it. A green liveness run proves only that the property was not violated; without a control that makes it fail on demand, "green" and "vacuous" are indistinguishable from the outside. `run.sh` gained a `failprop` expectation mode for it (TLC does not name the violated property, so NC5's config lists exactly one).

**On the NC trace lengths:** these are the traces *this* run reported, not canonical shortest paths — TLC runs `-workers auto` (18 here), and with parallel workers the reported safety counterexample is whichever violating state a worker reaches first, not a guaranteed minimum. The v0.9.2 record's NC1 (8 states, landing write = a protection *cancel*) and NC3 (9 states) are equally valid witnesses of the same hazards; NC2 and NC4 reproduce identically, and **NC4 is still the exact 11-state FM-1 trace**. What must stay stable is the *invariant* each control violates and the hazard it demonstrates — not the path length. (Recorded because Cx6-6 was a stale-counts finding: the fix for that is refreshing the numbers **and** saying which of them are load-bearing.)

Checked invariants (nominal): **I1** never-two-writers (no bot write lands post-latch pre-clearance; no actuator write lands un-latched — **every** venue write instrumented, the quiesce cancels included `[→ Cx6-4]`), **I2** host-independent coverage (`pos ≠ flat ⇒ plan Active`), **I3** evidence-gated terminals (`done`/tombstone ⇒ proved flat + final surfaces), **I4** lease releases only on tombstone, **I6** `HeldIncident ⇒ fence latched`, **I7** escalate-only arbitration, plus `TypeOK` — **and `P1`, the completion-capability action property `[→ Cx7-3]`**: no transition into `finalize` (uniquely `ActMarkFlat`, so the action form isolates the completion edge exactly) may occur without `ActuatorReady`. P1 is the regression check for Cx7-1, and it fills the gap that let seven green runs miss it: I1…I7 constrain writers, coverage, evidence-gating, the lease, held-honesty and escalation, but nothing tied a *completion* transition to *execution capability*. Liveness `[→ Cx6-5, Cx7-2]`: **two claims, both conditioned on an eventually-stable environment** (`EnvStabilizes == <>[] healthy` — no fairness scheme can force progress through guards an anti-phase flapping environment keeps permanently unaligned): **`IncidentResolves`** (operator-assisted — every incident eventually resolves: dismissal for a false alarm, clearance otherwise) and **`Branch12AutoResolves`** (`OPERATOR_INTERVENES = FALSE`, SF fills — the §9 branch-1/2 composite-guarantee *shape*: automated flat-with-final-surfaces or an honest escalation terminal (`HeldIncident`/`FenceUnavailable`/branch-3), never a silent stall, no operator rescue in the loop), **now split into `Branch1AutoResolves` + `Branch2AutoResolves` `[→ Cx7-2]`** (the combined form was *vacuous for branch 1*: its pre-latch stand-down disjunct holds on entry to every wind-down, since the actuator is not involved in branch 1 at all — so the Cx6-5 check only ever exercised branch 2 despite its name), **plus `P2`, the FM-3 stall regression** (`fenceCtl = takeover ∧ standby ∧ ¬latched ∧ exposure` is not a terminal state).

Negative-control traces (the model catches the documented hazards — each reproduces a specific spec warning):

Verbatim SM §4: "a transiently-crashed signer could restart mid-takeover and restore two writers." *(The v0.9.2 run reported an 8-state witness of the same violation whose landing write was a protection **cancel** — the Cx6-4 instrumentation observing exactly the write class it was added for. Both are valid; see the note above on worker nondeterminism.)*

The Cx5-1/R1d-F7 gate, shown load-bearing in 4 steps. **The run stops there** — `pos = "flat"`, `hadExposure = FALSE`; the fill into the coverage hole is **W2**, one step further on (5 states), and until slice E it was prose rather than a trace.

## 2. FM-1 — the finding this model surfaced against v0.9 (resolved v0.9.1)

**Trace (11 steps, minimal):** Replicate → WatchdogFire (host-silence; the entry never opened) → ActLatch → QuiesceDone → ReconcileDone → **ActMarkFlat** (durable `ActuatedFlat`) → **ActCrash** (the exact R1d-F7 window between `ActuatedFlat` and `Deactivate`) → **OpClearIncident** (spec-legal: the R1d-F6 clearance preconditions are the branch's terminal outcome *flat/reconciled* + propagation test — the plan tombstone is **not** among them) → **BotEntrySubmit under the same still-`Active` plan** (§6's "ack required before the entry submits" is satisfied by the *old* ack) → **ActDeactivate** — the stale re-driven tombstone lands, and the entry it re-admitted is still live → **I3**. *(Precisely: this run violates I3 and halts; `pos` is still `"flat"` and NC4 **never violates I2**. The step that makes the exposure real — and with it the I2 violation this paragraph is about — is one `VEntryFill` further on, which is **W6**, reached at 12 states in slice E. The reasoning below was right about the system for four review rounds while resting on a trace that stopped short of showing it.)* The harm, now demonstrated: open exposure with no `ListActive`-visible plan. The actuator would never protect that exposure. Host-independent coverage — the property the whole §6 lifecycle exists for — is broken by the composition of three individually-correct rules (R1d-F7 re-drive × R1d-F6 clearance × §6 ack-before-entry).

**Why it is a spec gap, not a model artifact:** nothing in core §7.4 / SM §3/§4/§6 (v0.9) states what becomes of a trade the takeover ran to completion evidence on. The bot-side close is terminal by construction (§6 step 9 sequences close finality → `Deactivate` → lease), but the actuator-side flatten leaves the trade's disposition unstated: the plan is still `Active`, the ack is still valid, and no rule forbids the cleared bot from re-admitting exposure under it while the tombstone re-drive is still owed.

**Resolution (v0.9.1, tagged `[→ FM-1]`):** **takeover completion evidence terminalizes the trade.** Once the durable `ActuatedFlat` record exists (equally: once any flatten of the trade reaches §2 finality with flat evidence), the trade re-admits no exposure-opening order; its plan lifecycle may only proceed to the §6 tombstone (re-driven across actuator restarts); fresh exposure is admitted solely as a **successor trade through the §6 lease**, which only that tombstone releases. Operator clearance restores trading for successors, never for the terminated TradeID. — The alternative fix (make the tombstone ack a clearance precondition) was **rejected**: it would couple operator clearance to plan-store availability, the same coupling R1d-5 rejected for hot-path generation acks; the terminality rule closes the hazard without it, because the lease already sequences successors on the tombstone.

**Normative edits:** core §7.4 (takeover bullet — terminality sentence), SM §4 (completion invariant), SM §6 (scope + actuator-side row note). Model: the `TRADE_TERMINALITY` constant guards `BotEntrySubmit` (nominal TRUE); **NC4 keeps the pre-fix world permanently reproducible.**

## 2b. FM-2 — found by the Cx6 liveness re-verification (resolved v0.9.2)

**Lasso (9-state loop, found by the post-Cx6 `IncidentResolves` re-check):** a **spurious watchdog fire** (bot alive and healthy — partition false positive) sets the incident; the actuator **crashes before `FenceLatch` completes** and stands back down (`standby`, nothing latched, no §3 branch ever started — `fenceCtl` never left ready/degraded, `branchMax = 0`). The un-fenced healthy bot keeps operating: its **obligated ≤5 s naked-reduce** (core §6.7) keeps submitting closes; the adversarial venue zero-fills every genuine reduction but **fills the close left live across the operator's manual flatten** — an over-close that re-creates naked exposure (the Cx6-1 non-atomic-kill race, working as modeled). So `flat ∧ no-live-orders` never holds at one instant, and `OpClearIncident` — the model's **only** incident exit — never enables. The loop is genuinely fair: the operator's cancel-all SF obligation is discharged by *extensionally identical* venue zero-fill steps (an action-aliasing subtlety worth remembering: TLA+ fairness constrains state-pair *predicates*, not intentions).

**Why it is a spec gap (minor), not only a model artifact:** the R1d-F6 exit ("return to normal operation requires the **branch's** terminal outcome flat/reconciled + clearance + fresh propagation test") is explicitly **scoped to a started branch** — but the spec stated **no exit at all** for an incident that started *no* branch and latched *nothing* (the false-positive fire the watchdog's design explicitly admits). With branch clearance as the only mechanism, acknowledging a false alarm would demand **flattening a healthy trade**. The model also omitted the operator's most basic spec power — the **kill-switch trip** (core §7.4 modes (a)/(c), the §7.3 control plane's first listed action) — leaving its operator to race a live bot's obligated resubmissions forever ("never two writers" includes the human).

**Resolution (v0.9.2, tagged `[→ FM-2]`):** a **false-positive fire that engaged nothing** (no epoch latched, no §3 branch started, bot verified alive) is **operator-dismissed as an alert**, never "cleared" — the branch-exit preconditions do not apply. Normative edits: core §7.4 (tiering bullet — dismissal sentence), SM §4 (spurious-fire stand-down/dismissal row). Model: `OpDismissFalseAlarm` (guarded `¬latched ∧ branchMax = 0 ∧ standby ∧ ready/degraded`) + `OpTripHalt` (the kill-switch trip: halts the bot during any incident; durable across reboot; supersedes the branch-1 wind-down obligation — the operator now owns the exit; gated by `OPERATOR_INTERVENES` as manual rescue, while dismissal is incident *administration* and stays ungated, like clearance). **Reproduction:** revert the two operator actions (or their fairness) and the `_Live` config re-produces the lasso — the pre-fix `.out` is the negative evidence; no NC config is added (the NC pattern is for safety-invariant hazards; this is a liveness gap, and the `_Live` run itself is its regression check).

## 2c. FM-3 — found by the Cx7 round-2 re-review (resolved v0.9.3)

**Lasso (`LiveSpec2`, `CRASH_BUDGET = 2`):** `BotReplicatePlan → BotEntrySubmit → VProtFire → VEntryTerminal → CtlLoss → CtlBranch1 → SignerCrash → ActReadyFlip → CtlEscalate1to2 → SignerRestart → ActCrash`, then cycling on `BackupFlip`. The loop state is the whole finding:

```
pos = "naked"        protLive = FALSE      plan = "active"     incidentActive = TRUE
fenceCtl = "takeover"    branchMax = 3     latched = FALSE
botUp = TRUE   signerUp = TRUE   botPhase = "winddown"   → the bot CAN sign, and is BARRED
actPhase = "standby"     actReadyOK = TRUE               → the actuator CAN trade, and is IDLE
```

Branch 2 engaged (durably — the arbitration is one-way per incident, R1d-F6), the actuator crashed **before** latching the epoch, and nothing ever re-engaged it: `ActResume` requires `latched`, and the only un-latched entry was `WatchdogFire`, whose fairness is scoped to real host silence (`WatchdogFireObligated == WatchdogFire ∧ ¬botUp`). Meanwhile the Cx6-1 write gate (`fenceCtl ∉ {manual, takeover}`) bars the healthy bot for the whole branch. **Unprotected exposure, both writers alive and idle, forever.**

**Why it is a spec gap, not a model artifact:** SM §4's standby re-entry row was scoped to the **watchdog / host-silence** path and its mid-takeover recovery row to `HeldIncident`; neither covered "un-latched actuator, active branch-2 incident, bot alive". The v0.9.2 spec treated the branch-2 hand-off as a *step that happens*, never as an **obligation that persists** — while making the bar on the bot durable. That asymmetry is the defect: the branch bars the bot **by branch**, not by the dimension that failed, so a branch that transfers the writer must guarantee the transferee actually engages.

**Isolation (the round's probe matrix, all self-run against the unmodified v0.9.2 module):**

| Probe | Specification | Result |
|---|---|---|
| G1 | `LiveSpec2` (no operator) | **VIOLATED** — the stall is real |
| G2 | `LiveSpec` (operator on) | **PASS** — the operator always breaks it; severity is bounded to the *automated* claim, and the v0.9.2 safety claims are unaffected |
| H1 | `LiveSpec2` + fair `WatchdogFire` | **PASS** — re-engagement is the fix |
| H2 | `LiveSpec2` + SF restored on all seven Cx6-downgraded arbitration constraints | **VIOLATED** — the SF→WF downgrade is **exonerated** (this was the round's most-anticipated attack surface) |

**Resolution (v0.9.3, tagged `[→ FM-3]`):** **engagement is a durable obligation, not a delivered message.** An actuator that boots — or stands back down — into an incident whose §3 branch is `TakeoverTransfer` with an **active plan and no latched epoch** MUST re-attempt the latch, keying off the durable branch record rather than a received hand-off signal (so a lost hand-off and a crashed actuator are the same case); the re-attempt is bounded exactly like the watchdog path, timing out to `FenceUnavailable` and the §3 tiered floor. **Normative edits:** core §7.4 (takeover bullet), SM §4 (a second standby transition row + a durable-engagement invariant), SM §3 (branch-2 row + the one-way invariant's corollary). **Model:** `ActReengage` (the un-latched sibling of `ActResume`) with `WF_vars` fairness — WF, not SF, because in the `EnvStabilizes` suffix the guard is persistent-until-fired. **Regression check:** `P2_NoBranch2Stall` in `_Live2.cfg`, plus `Branch2AutoResolves` no longer discharging the stall (Cx7-2). *Design note:* two alternatives were considered and rejected — re-arming the **watchdog** on an un-latched hand-off (puts stalled-takeover detection in the read-only watcher, and makes recovery depend on that domain being alive), and having the **bot re-drive** the hand-off until acked (puts the recovery obligation on the degraded party and re-introduces a host dependency into the takeover's own recovery path).

## 2d. FM-4 — found by the genuine round-2 re-review (Cx8; resolved v0.9.4)

**Provenance note first:** unlike FM-3, this one was found by an *independent* reviewer (a fresh Codex `artifact-review` on the v0.9.3 module), which wrote its own TLA+ probe module and produced the counterexample below. That is the round Cx7 owed and could not deliver.

**Lasso (`LiveSpec2`, `CRASH_BUDGET = 2`, reviewer-written property `LostEventuallyLeaves`):** `SignerCrash → CtlLoss → SignerRestart → BotCancelProt`, then cycling on `BackupFlip`. The loop state:

```
pos = "neutral"      plan = "active"      incidentActive = TRUE
fenceCtl = "lost"    branchMax = 0        → an incident was raised; NO branch was ever selected
botUp = TRUE   botPhase = "normal"   signerUp ∧ latchable ∧ actReadyOK   → EnvStabilizes HOLDS
actPhase = "standby"
```

`CtlLoss` recorded neither the failed dimension nor a decision, and all three branch actions re-read **live** health. After the signer restarts, `CtlBranch1` needs a live failed dimension and `CtlBranch2`/`CtlBranch3` both need live `¬SigningOK` — so **all three guards go false at once**, and WF cannot force an action that is no longer enabled. The incident sits in un-arbitrated `FenceReadyLost` forever: openings blocked, exposure open, no branch, no automated exit.

**Why it is a spec gap, not a model artifact:** SM §3 says the arbitration "branches on **which** dimension failed" — past tense, a property of the detected loss — while the model (and any implementation reading live health at decision time) branches on what is true *now*. The doc also states the health-driven return to `FenceReady` is permissible "**from `FenceDegraded` only** … the one-way rule governs `FenceReadyLost` onward", which says an entered `FenceReadyLost` does not un-enter — but the one-way rule was written scoped to a **started branch** (R1d-F6), leaving the detect→select window as an unstated silent escape.

**It also disproved a claim the model itself made.** The Cx6 SF→WF downgrade argument rested on branch guards holding *persistently* under `EnvStabilizes`. This trace is a guard enabled at one instant and never again — enabled infinitely often is not the same as persistent. The comment was corrected, and the property it defends is now true **by construction** rather than by argument.

**Severity bounding:** violates the *automated*-convergence claim only. Under `LiveSpec` the operator clears the incident, so `IncidentResolves` was green over it — the same way the v0.9.2 suite stayed green over FM-3. No safety invariant is affected.

**Resolution (v0.9.4, tagged `[→ FM-4]`, user-selected from three options):** **snapshot-and-commit.** The failure is recorded when the loss is detected and the arbitration branches on that **record**; a dimension that repairs inside the detect→select window does not abort the arbitration, exactly as it may not abort a started branch. The 2-vs-3 choice still reads **live** capability, deliberately — "a durable revoke is latchable *and* `ActuatorReady` is confirmed" is a claim about acting **now**, and handing off to an actuator that cannot trade would transfer the writer to nobody. Because branches 2 and 3 partition the live health space under a recorded signing loss, **exactly one guard is enabled throughout `fenceCtl = "lost"`**. *Rejected alternatives:* a health-driven return from `FenceReadyLost` when no branch had started (mirroring the FM-2 false-alarm dismissal — rejected because it converts the detect→select window into a silent escape from an incident that has already blocked openings, and the window is short enough that committing costs at most one controlled wind-down); and folding branch selection into loss detection atomically (rejected because it erases the interleaving window from the model, and that window is precisely where FM-1, FM-2 and FM-3 all hid).

**Normative edits:** core §7.4 (the one-way-per-incident sentence, extended from a *started* branch to a *pending* one) + SM §3 (transitions: the recorded-failure clause and a repair-before-selection row; invariants: the extended one-way rule; chaos: a new case) + core §9. **Model:** `signingAtLoss` (one bit — the only snapshot the branch rule reads; recording the unread dimensions cost 4.2× the state space for nothing). **Regression checks:** `P4_ArbitrationCompletes` in `_Live2.cfg` **and negative control NC5**, which restores the live-health guards and reproduces the lasso — so the property is *known to bite* rather than assumed to.

**One scoping correction to the reviewer's property.** `LostEventuallyLeaves` as written also fails on a **benign** trace: the bot dies before arbitration, the watchdog path legitimately takes over, exhausts its close budget and parks in `HeldIncident` — `fenceCtl` stays `"lost"` because branch selection is a bot action. That is an honest escalation terminal, not a strand. The permanent property is therefore scoped to `botUp ∧ branchMax = 0 ∧ actPhase = "standby"`, and its consequent admits actuator engagement — which hands the obligation to `Branch2AutoResolves` + `P3`, rather than treating engagement as itself a resolution.

### Deliberate model refinements found during checking (model-side, no spec change)

1. **Plan-scoped hand-off:** branch-2 engagement with no `Active` plan left the takeover unfinishable (nothing to tombstone). The takeover machine is plan-scoped (SM §4 standby holds *plans*); an incident with no plan resolves via clearance. Encoded in the three hand-off actions.
2. **Supersession completion:** the one-slot plan abstraction conflated trade identities when a legitimately-tombstoned trade was succeeded mid-`finalize`; per-TradeID stores ack `Deactivate(old)` idempotently. `ActDone` accepts `plan = active ∧ ¬actuatedFlat` (reachable only via old-tombstone → lease → replicate).
3. **I6 narrowed:** "held ⇒ plan Active" is the *actuator's-own-path* claim (it never tombstones from held without evidence), already carried by I2+I3 as state properties; a healthy bot may legitimately tombstone a manually-killed flat trade while the actuator's phase variable still reads `held`. I6 checks the fence half: `held ⇒ latched`.
4. **Liveness layer** (relative to the design doc; restructured by Cx6-5 + FM-2): the property generalized from "takeover terminates" to **`IncidentResolves`** (`incidentActive ~> resolved`) — the takeover-scoped antecedent mis-fired on a pre-latch actuator crash whose trigger evaporated (standby *is* that takeover's terminal, but the incident lives on bot-side). **Cx6-5 then split the claim:** a strongly-fair manual kill could rescue any stalled branch, so a single property proved only "the operator eventually clears" — `LiveSpec2` (`OPERATOR_INTERVENES = FALSE`, SF fills) now checks **`Branch12AutoResolves`**, the §9 branch-1/2 composite-guarantee *shape* (automated flat or an honest escalation terminal — `held`/`unavail`/branch-3/pre-latch stand-down — never a silent stall), with no operator in the loop; both properties carry the **`EnvStabilizes`** antecedent (`<>[] healthy` — no fairness scheme can force progress through guards an anti-phase flapping environment keeps permanently unaligned; the honest operational claim is "after the outage ends, the system recovers"). Fairness encodes the spec's obligations at the **weakest sufficient strength** (see Honesty notes): **WF** on the engine's arbitration/branch decisions (persistent-until-fired in the `EnvStabilizes` suffix), the obligated wind-down (`botPhase = winddown`), the obligated ≤5 s naked-reduce (core §6.7 — not only in wind-down), the obligated watchdog (`¬botUp`), the actuator protocol, venue resolutions; **SF** only where load-bearing — `ActLatch` (the latch↔unavail phase alternation keeps its enabling intermittent even in a stable environment) and the five operator actions — **trip-halt, flatten, cancel-all `[→ FM-2, Cx6-1]`, dismissal, clearance** (branch 3/held/unavail are operator-resolution *targets*; the enabling windows can be made intermittent). Spurious watchdog fires, crashes (bounded by `CRASH_BUDGET = 2` in the liveness configs only), env flapping, and discretionary bot behavior stay adversarial.
5. **Manual kill made real (Cx6-1) and the operator powers completed (FM-2):** the original atomic `OpManualKill` erased the UI race a real cancel-all + close has — split into `OpManualFlatten` + `OpManualCancelAll` with **over-close fill semantics** (`VBotCloseFill`/`VActCloseFill` on an already-flat package create reverse exposure — the late-fill-after-manual-flatten hazard family). That split is what exposed the FM-2 lasso (§2b), whose fix added the two missing operator powers: `OpTripHalt` (the core §7.4 kill-switch trip — durable across reboot; ends the operator-vs-bot race) and `OpDismissFalseAlarm` (the no-branch false-alarm exit). An instructive fairness subtlety from that debug: **SF obligations can be discharged by extensionally identical steps of a different action** (a venue zero-fill of the only live order *is* the cancel-all, as a state-pair predicate) — intentions are not part of TLA+ fairness.

6. **Capability gating completed and the convergence property de-vacuated (Cx7-1/-2/-3, model-side; the SM was already normative and correct on all three).** Cx6-2 had gated the takeover's *entrances* — the latch and every venue write — but left the **progress and completion** actions (`ActQuiesceDone`, `ActReconcileDone`, `ActMarkFlat`, `ActDeactivate`) ungated, with `held` still in `ActMarkFlat`'s phase set, so `held → finalize → tombstone` walked back out of the Cx6-2 park and asserted a plan-store write the health state calls impossible (Cx7-1). Sealing it required adding the park's *other* spec-stated exit as a real action (`ActHeldReentry`) — otherwise the safety escape becomes a liveness dead end. `Branch12AutoResolves`'s stand-down disjunct was then found to be discharging FM-3's stall, on a rationale ("the healthy bot remains the writer") that **Cx6-1 had falsified in the same round**, and to be vacuous for branch 1; it is now split and conditioned (Cx7-2). And nothing in `I1`…`I7` tied a completion transition to execution capability — which is *why* seven green runs missed Cx7-1 — so `P1` is now a permanent suite member (Cx7-3). **A methodological note from P1's own first run:** stated as `actPhase' = "finalize" ⇒ actReadyOK` (the round's probe form) it also constrains every step that merely *remains* in `finalize`, and reported a false violation on an unrelated step taken after readiness dropped; the permanent form is scoped to the **edge** (`actPhase ≠ "finalize" ∧ actPhase' = "finalize"`). A probe good enough to *find* a bug is not automatically good enough to *guard against* it.

## 4. Honesty notes / limits

- **Small-scope claim:** passing nominal runs are evidence over *this* abstraction (one trade, qualitative exposure, observed=truth health), not proof at implementation scale. §9 chaos tests remain the implementation gate. The model's value: it exhausts crash × restart × partition × reorder interleavings prose review does not — and it found FM-1 in the first nominal run.
- **Monitoring lag** (observed health ≠ truth) and **multi-trade concurrency** are the two named refinement candidates if this model is extended.
- **Green runs prove only what the properties say (Cx7).** Two of Cx7's four findings were escapes the *suite* could not see: a completion path with no capability property over it (Cx7-1/-3), and a liveness property whose escape hatch certified the very stall it should have caught (FM-3/Cx7-2) — the suite was 7/7 green over both. The standing lesson recorded with the round: **exit and resumption paths are the blind spot.** Cx6 hardened every entrance (latch gate, branch guards, write gates); Cx7's holes were "how do you get out of `held`" and "how do you get back in after a crash" — and, at the meta level, "how does a property let itself off the hook".
- Liveness is a conditional claim: an eventually-stable environment (`EnvStabilizes`), finitely many crashes (`CRASH_BUDGET = 2`), + the stated fairness (operator eventually acts — including the FM-2 dismissal of false alarms and the halt-first manual procedure). Safety runs have **unbounded** crashes. **Fairness minimality (Cx6 close-out):** arbitration/branch fairness is **WF, not SF** — in the `EnvStabilizes` suffix those guards are persistent-until-fired (within an incident, `latched` is monotone; un-latch = clearance = resolution), so the claims hold under the *weaker* assumption (the stronger theorem); SF is retained only where genuinely load-bearing — `ActLatch` (the latch↔unavail phase alternation keeps its enabling intermittent even in a stable environment) and the five operator actions (windows made intermittent by position/order/phase dynamics). Checking uses `run.sh`'s `-lncheck final` (one liveness pass over the completed graph; TLC's default periodic passes over the growing graph made these configs impractically slow).
- I5 (tombstone permanence) is discharged by the port contract, not checked — see the SM §6 map row.
- **The fairness set's core §6.7 premise was RE-DERIVED on 2026-08-09, not re-run (task #232, record §92) — and the re-derivation moved the premise onto a THIRD section.** §88's freshness gate reported core §6 changed since 310e854, which for a `premise` row means a recorded justification may have expired while every run stayed valid: the FM-7 class. What is at stake is item 4 above — WF on *the obligated ≤5 s naked-reduce (core §6.7 — not only in wind-down)* — and the FM-2 lasso analysis, which needs the un-fenced healthy bot to *keep submitting closes*. **Step 7's entire delta across that boundary is three edits**, and the sentence the fairness set encodes (*"immediately (≤5 s, §9) issues an `ExposureReduction` … for a determined residual"*) is **byte-identical**. Two of the three are #231's producer-list correction, which this model does not encode. The third is the FM-5-family clause, and it is the one that could have mattered: it adds a state in which the handler **holds new trading**, and fairness assumed over a guard the spec has since narrowed is fairness *stronger than the spec grants* — the direction that proves liveness the system does not have. It does not bite, for a reason that lives **outside** core §6: core §7.5 rules that hold **stop-opening** rather than halted, *"the order may be executing, so the safety verbs must stay available"*, and the ≤5 s determined flatten is a safety verb. FM-2's lasso is clear twice over, since its bot is **healthy by construction** and the guard's antecedent is false in that trace. **So the justification now consumes core §7.5, and core §7.5 is tracked in `freshness.json` from this date** — an edit widening that hold to a full halt would void this paragraph with no run changing and no invariant going red, which is precisely what a premise row is for.
- **A control's verdict and a control's evidence are different claims (slice E item 2).** Every NC here reports the invariant it was predicted to violate, and for four rounds that was read as the hazard being demonstrated. It is not: TLC returns *a* counterexample, and where a hazard has a cheap surrogate one step shallower than the real thing, breadth-first search returns the surrogate every time. The witness probes W1–W6 are the standing answer, and the rule they encode is: **when a control's config comment names a harm, the harm is a run or it is a hypothesis.** The two places this artifact narrated past its own traces (§1's NC2 line, §2's FM-1 trace) are marked in place rather than quietly corrected, because the failure mode is the prose being *right* — a wrong claim gets challenged, a true one resting on a run that did not show it does not.

## 5. How to run

```
cd docs/formal && ./run.sh
```

Fetches `tla2tools.jar` v1.7.4 (SHA-256 pinned) into gitignored `.tools/`, then runs all **fourteen** configs and checks each against its prediction (nominal safety + both liveness configs must pass; NC1–4 must fail on the predicted invariant; **NC5 must fail on the predicted temporal property**; **W1–W6 must each be VIOLATED — they state the harmful state is never reached, so a PASS is the failure**). Requires Java 17+. Full outputs land in `.tools/*.out`. **≈32 min** on 18 cores; the `_Live2` config dominates at 23 min (five temporal properties over its graph).

**Clear `.tools/states-*` before a full unfiltered run.** TLC keeps one `-metadir` per config and never reclaims them, so the suite accumulates them across sessions — measured 2026-08-02 at **12 GB over 114 directories**, and a full run under that pressure killed `_Live2`'s JVM with **SIGBUS in an mmap'd `arraycopy`** as the temporal phase started. The tell that it is environmental rather than a model regression: the *safety* phase had already reproduced this artifact's recorded graph exactly (1,705,418 / 249,936), and the crash is a JVM fault rather than a violated property. `rm -rf .tools/states-*` is safe and loses nothing — the `.out` files are the results, the metadirs are scratch — and it took the directory from 12 GB to 3.2 MB. Worth doing as a matter of course beside a long-running market-data capture, where disk is the shared resource that cannot be re-fetched.

**Reviewer-authored probes — `docs/formal/probes/`** (not part of `run.sh`). The Cx8 round's two properties, written by the independent reviewer rather than by this model's author, kept under version control for exactly that reason. `ExhaustedHeldEventuallyParks` **passes** on the current module and is the independent confirmation of Cx8-2; `LostEventuallyLeaves` **still fails by design** on a benign watchdog-park trace (§2d's scoping correction). Read `probes/README.md` before running them — the failure is expected and must not be "fixed" into the model.
