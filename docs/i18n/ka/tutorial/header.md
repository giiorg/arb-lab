# funding rate-ის არბიტრაჟის ბოტის შექმნა — სახელმძღვანელო

**Status:** v0.9.9 (2026-07-27) — set-version alignment, no change in this doc (v0.9.9 is the **fourth-slice release**: core §3.5/§4, from building `engine/venue` — the market-data seam resolved to one shape and one name, a `SourceID` refusing an `(instrument, stream)` pair no venue can produce, and a units discipline for the venue fields that are **durations**. The first two are **seam mechanism below this tutorial's altitude**. The third is not, quite, and it is worth saying why it still changes nothing here: **1.7 already teaches that the funding interval is live state**, that Bybit auto-switches an alt between 8h and 1h and reverts without notice, and that a mid-position flip must be detected — and core §4 now requires the interval to be **refused rather than defaulted** when a venue does not send it, so that a flip cannot be quietly absorbed by an 8h fallback. That is 1.7's lesson given an implementation rule, not a new lesson: the teaching point — the number you assumed was a constant is the one that moves — is unchanged, and the arithmetic that divides a hold by that interval — 1.5's `$10 every 8h → ~10.95% APR`, and Part 3's worked trade counting **~25 settlements** before costs are covered — is exactly what the rule protects). v0.9.8 was likewise alignment-only here (the **third-slice release**: core §3.2/§3.4/§3.5/§3.6/§4, from building `marketdata` on the funding path — which sequence number a dispatched envelope carries and when, that a source's priority may not vary with what it publishes, one freshness budget measured against two clocks, and the `Envelope` rather than the payload owning provenance. All are **dispatch and provenance mechanism this tutorial points at rather than teaches**; the closest neighbour is Part 3's account of why a stale mark is dangerous, whose *detection* core §3.4 now specifies as two measurements against one budget — the teaching point, that a feed can die without emitting anything, is unchanged). v0.9.7 was the **re-judgement release**: four normative statements the shared kernel's code makes, landed into core §3.2/§7.5/§7.6/§10 — the outbox's sequence-as-dedup-key and committed-bytes payload, reconcile-only as a four-rung **posture** rather than a boot stage, the rate limiter's upward-only header correction and retry-hint-as-floor, and the integer-typed recording seam with unit and asset tags.
