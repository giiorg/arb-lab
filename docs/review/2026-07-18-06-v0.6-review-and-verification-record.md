## 2. Venue verification (official docs, 2026-07-18)

### Bybit UTA account posture
- **Headline correction:** "isolated margin AND per-coin collateral-switch-off" is **not jointly achievable** — collateral customization exists only in Cross/Portfolio mode. Clean posture = account-level `ISOLATED_MARGIN` (per-position liquidation is the segregation). → https://www.bybit.com/en/help-center/article/Differences-Between-the-Margin-Modes-Under-the-Unified-Trading-Account
- Margin mode: `POST /v5/account/set-margin-mode {setMarginMode:ISOLATED_MARGIN}`; read `GET /v5/account/info.marginMode`. UTA2.0 margin mode is account-level. → https://bybit-exchange.github.io/docs/v5/account/set-margin-mode · https://bybit-exchange.github.io/docs/v5/account/account-info
- Spot borrow off: `isLeverage=0` on `POST /v5/order/create` (spot); spot-margin `POST /v5/spot-margin-trade/switch-mode 0`, status `GET /v5/spot-margin-uta/status`. → https://bybit-exchange.github.io/docs/v5/order/create-order · https://bybit-exchange.github.io/docs/v5/spot-margin-uta/status
- `unifiedMarginStatus` enum: 1=Classic, 3/4=UTA1.0, 5/6=UTA2.0; classic unavailable to new accounts (Dec-2024 migration). → https://bybit-exchange.github.io/docs/v5/enum · https://bybit-exchange.github.io/docs/v5/acct-mode
- Boot/pre-trade assert: marginMode==ISOLATED_MARGIN (load-bearing), spotHedgingStatus==OFF (`set-spot-hedge`), auto-add-margin OFF per symbol, borrowAmount==0 ∧ spotBorrow==0. "Spot not seized" holds under Isolated (per-position loss cap; no account-level MMR liquidation) — **testnet liquidation test recommended before real capital.** → https://www.bybit.com/en/help-center/article/Liquidation-Price-Calculation-under-Isolated-Mode-Unified-Trading-Account

### Binance account posture + attached protection
- Segregated spot vs USDⓈ-M futures wallets; futures liquidation uses the futures wallet only (hedged spot does NOT protect the perp). **Portfolio Margin / Unified MUST be OFF.** → https://www.binance.com/en/support/faq/how-to-transfer-funds-to-the-futures-wallet-360033773532 · Multi-Assets FAQ https://www.binance.com/en/support/faq/frequently-asked-questions-on-the-multi-assets-mode-f80415bea8124f6494566f23c0bf9c38
- Single-Asset Mode: `POST/GET /fapi/v1/multiAssetsMargin` (`false`). Multi-Assets forces Cross → mutually exclusive with Isolated. Isolated margin: `POST /fapi/v1/marginType {ISOLATED}`; read `symbolConfig`/`positionRisk`. → https://developers.binance.com/docs/derivatives/usds-margined-futures/trade/rest-api/Change-Multi-Assets-Mode · .../Change-Margin-Type
- **No atomic attach-on-entry on USDⓈ-M futures:** New Order has no TP/SL param; conditional types moved to Algo Service (`POST /fapi/v1/algoOrder`) 2025-12-09, and `/order` now returns **-4120**; no futures OCO/bracket. → https://developers.binance.com/docs/derivatives/change-log · .../New-Order
- SPOT has OCO/OTOCO (`/api/v3/orderList/oco|otoco`, LIMIT working order only). → https://developers.binance.com/docs/binance-spot-api-docs/rest-api/trading-endpoints
- **Conclusion:** the first-fill→protection-ack window on the Binance perp leg **cannot** be closed venue-natively → an external pre-armed actuator is required (drives the $1K-tier decision).

### Spot surface + order recovery
- Bybit recovery: `GET /v5/order/realtime` = open + last ~500 closed, **cleared on server restart** ("...should only be queried through order history"); fallback `GET /v5/order/history` by `orderLinkId` (~2yr; a filled order is always recoverable). → https://bybit-exchange.github.io/docs/v5/order/open-order · https://bybit-exchange.github.io/docs/v5/order/order-list
- Binance spot user-data: separate listenKey `POST /api/v3/userDataStream` (deprecated → WS-API `userDataStream.subscribe`, needs Ed25519 `session.logon`). Spot order/query/fills: `/api/v3/order`, `/api/v3/openOrders`, `/api/v3/myTrades`. Filters via `/api/v3/exchangeInfo` (LOT_SIZE/PRICE_FILTER/NOTIONAL). Spot book on `stream.binance.com` (`@depth`), not fstream. → https://developers.binance.com/docs/binance-spot-api-docs/rest-api/account-endpoints · .../filters
- **No mark/index/funding on spot** (both venues) — value/freshness-check the spot leg from its own book; Bybit spot `usdIndexPrice` is a USD-conversion ref, not a mark. → https://bybit-exchange.github.io/docs/v5/websocket/public/ticker
- Rate limits: Binance spot vs futures report/enforce **separate** used-weight/order budgets via their own exchangeInfo → governor per (venue, API family). IP-ban-track separation is inferred, not doc-confirmed.
