## Findings

### FM-1 — VALID (spec under-specification; normative fix applied)

**Claim:** the v0.9 rules admit a reachable composition in which host-independent coverage — the property the §6 plan lifecycle exists to provide — is silently revoked under live exposure.

**Counterexample (TLC, 11 steps; permanently reproducible as `docs/formal/FenceTakeover_NC4.cfg`):** plan replicated → watchdog fires on host silence → takeover latches, quiesces, verifies flat → durable `ActuatedFlat` persisted → **actuator crashes in the R1d-F7 window before `Deactivate`** → operator clears the incident (spec-legal: R1d-F6 clearance preconditions are flat/reconciled + propagation test — the tombstone is not among them) → bot resumes and **opens fresh exposure under the same still-`Active` plan** (§6 "ack required before the entry submits" is satisfied by the old ack) → the actuator's re-driven `Deactivate` lands → **tombstone under live exposure**; `ListActive` no longer returns the trade; a subsequent host death is uncovered. Three individually-correct v0.9 rules (R1d-F7 re-drive × R1d-F6 clearance × §6 ack-before-entry) compose into the hazard; the bot-side close path is immune only because §6 step 9 sequences close → `Deactivate` → lease within one owner.

**Triage:** valid — nothing in v0.9 states the disposition of a trade the takeover ran to completion evidence on. Found on the model's **first nominal safety run** (violation of the evidence-gated-terminal invariant, then coverage).

**Resolution (applied, tagged `[→ FM-1]`):** **completion evidence terminalizes the trade** — once `ActuatedFlat` exists (equally: once any flatten reaches §6.7 finality with flat evidence), the trade re-admits no exposure-opening order; its plan may only proceed to the tombstone (re-driven across restarts); fresh exposure is admitted solely as a **successor trade through the hedge-group lease**, which only that tombstone releases; clearance restores trading for successors, never for the terminated `TradeID`. **Alternative rejected:** making the tombstone ack a clearance precondition — couples operator clearance to plan-store availability (the same coupling R1d-5 rejects for hot-path generation acks); unnecessary once terminality holds, because the lease already sequences successors on the tombstone.

**Edits:** core §7.4 (takeover bullet — terminality passage + rejected alternative), core header (Conventions: `FM-#` tag class; Status), SM §3 (clearance note: deliberately does not wait on the tombstone, safe *because* of FM-1), SM §4 (completion invariant), SM §6 (terminal-trade invariant bullet), ADR §2/§3 (record index + FM block), Profiles/tutorial (set-version alignment stamps only).

## Findings + dispositions

- **Cx6-1 (BLOCKER) — `ManualOnly` wasn't manual-only.** After branch 3, a signer restart re-enabled automated bot closes and protection cancels (`BotCloseSubmit`/`BotCancelProt` checked phase + signing but not the branch), contradicting "bounded pre-armed protection + operator manual kill only" — and in branch 2 the transferred writer was similarly un-enforced against a restored signer. Second-order: the atomic `OpManualKill` erased the real UI race (a previously-accepted close filling *after* the manual flatten). **Fixed (model):** bot venue writes gate on `fenceCtl ∉ {manual, takeover}` (pre-branch `lost` stays permissive for closes — first-safe-action blocks openings only); manual kill split into non-atomic `OpManualFlatten` + `OpManualCancelAll`; over-close fill semantics added (a close filling on an already-flat package creates reverse exposure). Spec unchanged — SM §3/§4 were already normative on both points; the model had weakened them.
- **Cx6-2 (MAJOR) — `ActuatorReady` didn't constrain the watchdog takeover or actuator execution.** The model could complete a takeover after the actuator's own credential/reachability/plan-store had failed (production cannot perform those writes). **Fixed (model + spec):** `ActLatch` requires `actReadyOK` (engaging with no execution capability transfers the writer to nobody — the branch-2 rationale applied to the watchdog path; a failed-ready engagement times out to `FenceUnavailable`); every actuator venue write (quiesce cancels included) requires execution readiness; new `ActReadyLostMidTakeover → HeldIncident` edge. **Normative edits:** SM §4 (latch-gate + mid-takeover row + execution-authority invariant), core §7.4 (execution-capability clause) `[→ Cx6-2]`.
- **Cx6-3 (MAJOR) — clearance could declare `FenceReady` while the fence was unhealthy.** `OpClearIncident` had no health guard and always restored "ready". **Fixed (model + spec):** clearance requires `signerUp ∧ latchable ∧ actReadyOK` (the fresh propagation test cannot pass on a failed dimension) and returns **`FenceDegraded`** while only the backup is failed. **Normative edit:** SM §3 (one-way/clearance invariant — "clearance is health-gated") `[→ Cx6-3]`.
- **Cx6-4 (MAJOR) — I1 didn't observe all actuator venue writes.** The four quiesce-cancel actions never updated the unfenced-landing flag, so an unfenced cancel escaped the single-writer check. **Fixed (model):** every actuator venue action records `actLandedUnfenced` exactly like a close.
- **Cx6-5 (MAJOR) — the liveness pass didn't prove branch-1/2 automated convergence.** A strongly-fair manual kill could rescue any stalled wind-down/takeover, so `IncidentResolves` proved only eventual operator clearance. **Fixed (model):** `OPERATOR_INTERVENES` constant; `LiveSpec2` + **`Branch12AutoResolves`** (`FenceTakeover_Live2.cfg`: no operator rescue, SF fills) checks the §9 branch-1/2 composite-guarantee shape — automated flat-with-final-surfaces or an honest escalation terminal (`HeldIncident`/`FenceUnavailable`/branch-3/pre-latch stand-down), never a silent stall; both liveness claims conditioned on **`EnvStabilizes`** (`<>[] healthy` — no fairness scheme forces progress through guards an anti-phase flapping environment keeps permanently unaligned).
- **Cx6-6 (MINOR) — recorded state counts didn't describe the reviewed module** (stale since the `hadExposure` fix). **Fixed:** counts + revision identifier refreshed in `fence-takeover-model.md` §1 and the verification section below; the v0.9.1 numbers above are annotated as historical.

## FM-2 — found by the round's liveness re-verification (normative fix applied)

Re-running `IncidentResolves` over the Cx6-fixed model produced a **fair 9-state lasso**: a spurious watchdog fire (bot alive/healthy — the false positive the design explicitly admits) with the actuator crashing pre-latch leaves an incident that **started no branch and latched nothing** — and the model's only exit, `OpClearIncident`, demands the R1d-F6 branch-exit preconditions (`flat ∧ no-live-orders`), unreachable while the un-fenced healthy bot's **obligated ≤5 s naked-reduce** races the operator's non-atomic manual kill (every flatten gets over-closed by the close left live across it; the operator's cancel-all SF obligation is discharged by extensionally identical venue zero-fills — fairness constrains state-pair predicates, not intentions).

**Triage: valid, minor, spec gap + model-fidelity gap.** Spec side: R1d-F6's exit is explicitly scoped to "the **branch's** terminal outcome" — but v0.9.1 stated **no exit at all** for an incident that engaged nothing; with clearance as the only mechanism, acknowledging a false alarm would demand flattening a healthy trade. Model side: the operator lacked the spec's most basic power — the **kill-switch trip** (core §7.4 modes (a)/(c), §7.3 control plane) — without which "never two writers" cannot include the human.

**Resolution (tagged `[→ FM-2]`):** a false-positive fire that engaged nothing (no epoch latched, no §3 branch started, bot verified alive) is **operator-dismissed as an alert**, never branch-cleared. **Edits:** core §7.4 (tiering bullet — dismissal sentence), SM §4 (spurious-fire stand-down/dismissal row), model (`OpDismissFalseAlarm` + `OpTripHalt`, both SF; halt durable across reboot, gated by `OPERATOR_INTERVENES`; dismissal ungated — incident administration, like clearance). **Reproduction:** revert the two operator actions and `_Live` re-produces the lasso (no NC config — the NC pattern is for safety hazards; the `_Live` run is this gap's regression check). Full trace + analysis: `fence-takeover-model.md` §2b.

## Findings + proposed dispositions — **NONE APPLIED**

- **FM-3 (MAJOR) — spec silence: no obligation to re-engage a branch-2 takeover after a pre-latch actuator crash.** Branch 2 engages (`fenceCtl = takeover`, `branchMax = 3`, durable per R1d-F6 one-way), the actuator crashes **before** latching the epoch, and nothing ever re-engages it. SM §4's standby re-entry row (`ListActive` reconcile-only boot) is scoped to the **watchdog / host-silence** path; SM §4's mid-takeover recovery row is scoped to `HeldIncident`. Neither covers "un-latched actuator, active branch-2 incident, bot alive". Meanwhile Cx6-1's write gate (`fenceCtl ∉ {manual, takeover}`) **permanently bars the healthy bot**, because R1d-F6 forbids a restored signer from aborting a started branch. **Reachable end state: naked unprotected exposure, both writers alive and idle, forever.** *Model-side symptom:* `ActResume` requires `latched`; the un-latched path is `WatchdogFire`, which is fair only via `WatchdogFireObligated == WatchdogFire ∧ ¬botUp`. **Proposed resolution (spec, core §7.4 + SM §4):** an actuator that boots (or stands down) into an incident whose §3 branch is `TakeoverTransfer` with an active plan and no latched epoch **MUST re-attempt `FenceLatch`** — the branch-2 hand-off is durable state, so the obligation survives the crash; the existing `T_fence` timeout then routes a failed re-attempt to the `FenceUnavailable` floor as usual. This is the state the disjunct in Cx7-2 was silently calling "resolved".
- **Cx7-1 (MAJOR, model fidelity — spec already correct) — the takeover records completion without execution capability.** `ActQuiesceDone`, `ActReconcileDone`, `ActMarkFlat` and `ActDeactivate` carry **no `actReadyOK` guard**, and `ActMarkFlat`'s phase set includes **`held`**. SM §4:264 is already normative and correct ("the protocol cannot progress and parks honestly: fence stays latched, plan stays `Active`"); **the model weakened it**, exactly as Cx6-1 had weakened SM §3/§4. **Proposed resolution (model only, no spec edit):** gate the intra-takeover progress and completion actions on `actReadyOK`, and remove `held` from `ActMarkFlat`'s phase set (exit from `held` is the operator path or re-entry once ready — SM §4:264's own words).
